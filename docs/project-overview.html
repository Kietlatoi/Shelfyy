Sản phẩm

Shelfy là gì?

Shelfy là ứng dụng quản lý tủ đồ cá nhân. Người dùng có thể đăng ký, đăng nhập, lưu trữ món đồ trong tủ, upload ảnh trang phục, xem thống kê tủ đồ và nhận gợi ý phối đồ.

Kiến trúc microservice-oriented

BE/Shelfy hiện là Core API Service đang chạy production, không phải toàn bộ hệ thống cuối cùng. Các năng lực mới từ thời điểm hiện tại sẽ ưu tiên triển khai trong Nodejs; không mở rộng thêm code Java nếu không có quyết định kiến trúc riêng.

Quản lý tủ đồ Lưu món đồ, ảnh, màu sắc, category, size, chất liệu, tag, số lần mặc và trạng thái yêu thích.
Gợi ý theo ngữ cảnh Mặc định dùng rule-based stylist để phối đồ theo tủ đồ, thời tiết thật và lịch trình từ calendar.
AI try-on Tạo ảnh mô phỏng người dùng khi mặc một trang phục bằng Replicate IDM-VTON.
  • Người dùng mục tiêu: cá nhân muốn quản lý tủ đồ và chọn trang phục hằng ngày hiệu quả hơn.
  • Tên chính thức của dự án: Shelfy.
  • Ưu tiên hiện tại: login, register, profile cá nhân, lưu trữ đồ, weather/calendar Nodejs, outfit mặc hôm nay và nối FE với các service production.

Backend

Core API Service

BE/Shelfy là Core API Service hiện tại trong kiến trúc microservice của Shelfy. Service này dùng Spring Boot 3.3.5, Java 17. Database migration dùng Flyway.

Package Vai trò

dto.requestRequest DTO.

JWT security

Access token gửi qua Authorization: Bearer <token>. Refresh token raw trả về FE, bản hash SHA-256 lưu trong DB. FE gọi /api/auth/refresh bằng refresh token body, lưu access token và refresh token mới vì Core API đang dùng refresh token rotation. FE dùng single-flight refresh để nhiều request đồng thời không cùng dùng một refresh token cũ và tự làm hỏng session.

Constraint cần nhớ

wardrobe_items.category nhận các nhóm như TOP, BOTTOM, DRESS, SHOES, BAG, ACCESSORY, OUTERWEAR, OTHER. wardrobe_item_preferences.item_status gồm IN_USE, RARELY_USED, STORED, TO_SELL. try_on_sessions.status gồm PENDING, PROCESSING, COMPLETED, FAILED. users.storage_limit = -1 nghĩa là không giới hạn.

AI và dịch vụ ngoài

Tích hợp sắp triển khai

Rule-Based Stylist

Gợi ý trang phục hiện dùng rule engine trong Nodejs Service. Nodejs chấm điểm item theo thời tiết, lịch trình, chất liệu, màu, mùa, favorite/trạng thái và lịch sử mặc gần đây để trả structured JSON. Gemini có thể được bật lại sau cho phân tích ảnh hoặc viết lại text.

Replicate IDM-VTON

Try-on dùng Replicate API với model cuuupid/idm-vton:0513734a452173b8173e907e3a59d19a36266e55b48528559432bd21c7d7e985. Input là ảnh người dùng và ảnh trang phục; output là ảnh mô phỏng người dùng mặc trang phục.

Open-Meteo và Nominatim

Weather dùng Open-Meteo trong Nodejs Service. FE gửi tọa độ hiện tại lên Nodejs; Nodejs gọi Open-Meteo, map weather_code sang mô tả tiếng Việt, gọi Nominatim reverse geocoding để lấy location_label, lưu snapshot vào Postgres và trả dữ liệu chuẩn hóa. Nếu reverse geocoding lỗi hoặc không tìm được tên địa điểm, Nodejs vẫn trả dữ liệu thời tiết thật và dùng nhãn Vị trí hiện tại, không tự sinh tên thành phố giả. Nếu user không cấp quyền vị trí, FE báo lỗi rõ và không dùng dữ liệu giả.

Google Calendar

Calendar thật do Nodejs xử lý. FE không gọi trực tiếp Google Calendar API và không dùng /api/events của Java cho màn /home. Luồng hiện tại là OAuth, lưu token đã mã hóa, gọi Google Calendar API, chuẩn hóa dữ liệu, lưu lại cho suggestion và trả qua Nodejs API như /api/calendar/today. Các biến chính gồm GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET, GOOGLE_CALENDAR_REDIRECT_URI, GOOGLE_CALENDAR_SCOPES và CALENDAR_TOKEN_ENCRYPTION_KEY.

Secrets

Bảo mật và env

Không commit file chứa secret

Không commit .env, .env.local, *.env hoặc file copy như BE/.env (1). Các giá trị như JWT secret, database password, Cloudinary key, Replicate token và VNPay secret phải nằm trong môi trường deploy hoặc env local không commit.

Biến public FE

FE chỉ được commit biến public kiểu VITE_API_BASE_URL, VITE_NODE_API_BASE_URL khi giá trị không phải secret. URL production là public endpoint nên có thể nằm trong env deploy.

Ghi nhớ

Lưu ý hiện trạng

  • FE production dự kiến deploy Vercel.
  • Core API Service production đang deploy Railway.
  • Database production dùng PostgreSQL Railway.
  • FE gọi thẳng Core API Service trên Railway và gọi thẳng Nodejs Service qua VITE_NODE_API_BASE_URL.
  • Profile cá nhân đã có màn riêng ở FE và dùng các endpoint /api/users/me, /api/users/me/password.
  • Java đã xóa /api/home; weather thuộc Nodejs Service.
  • Tính năng mới từ hiện tại ưu tiên triển khai bằng Nodejs; không thêm code Java cho feature mới nếu không có quyết định riêng.
  • demo@shelfy.app / 123456 hiện không login được trên Railway; cần sửa seed credential nếu muốn dùng demo account.
  • Payment chưa chốt flow production.
  • Weather dùng Open-Meteo và Nominatim, không cần API key ở giai đoạn hiện tại.
  • Calendar trên /home đã bỏ nguồn /api/events Java; hiện gọi Nodejs Calendar API để kết nối Google Calendar thật và lấy lịch hôm nay.
  • Outfit mặc hôm nay đã có boundary Nodejs: FE /wardrobe gọi POST /api/daily-outfits để xác nhận bộ đồ sẽ mặc; FE /wear-history gọi GET /api/daily-outfits để xem lịch sử mặc lưu trong daily_outfits.
  • Favorite và trạng thái món đồ đã có boundary Nodejs: FE /wardrobe và /favorites gọi GET /api/wardrobe/preferences để merge metadata vào item từ Java và gọi PUT /api/wardrobe/items/{id}/preferences khi user thích hoặc đổi trạng thái item.
  • Gợi ý hôm nay đã có boundary Nodejs: FE /suggest gọi GET /api/suggestions/today/latest, POST /api/suggestions/today và POST /api/suggestions/{id}/confirm; mặc định dùng rule-based stylist, không cần Gemini API key.
